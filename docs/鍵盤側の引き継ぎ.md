# 引き継ぎ：Piano Falls（鍵盤側）

このファイルは、鍵盤側の作業を続ける会話と、ドラム側（drum）の作業をする会話の両方が読みます。
- **鍵盤側の会話**：作業を始める前に、これと `CLAUDE.md`、同期の仕様、ドラム側の引き継ぎを読む。変えたことがあれば、ここを更新する。
- **ドラム側の会話**：同期まわりで鍵盤側がどう動くかを知るために読む（「同期の実装」と「ドラム側への提案」）。このファイルと、鍵盤側のソフトのファイルは書き換えない。
- **同期の約束ごと**：正式なものは drum リポジトリの `同期の仕様.md`。鍵盤側からは直さず、変えたいことは下の「ドラム側への提案」に書く。

## 作業の決まり
`CLAUDE.md` に書いてある。要点：返事は日本語、ソフトは1ファイル、機能を変えたら配布ページと引き継ぎも直す、`node --check` と Playwright で確かめる、ユーザーは MIDIキーボードを持っていない（MIDI機器が要る機能は未テストと書く）、GitHub に上げる前に必ず文章で聞く、ページやファイルを更新したら配布ページのURLを書く、ドラム側のファイルと同期の仕様は書き換えない。

## 主な機能（2026/10/24 時点）
- **表示**：MIDIファイルを読み込み、落ちてくるノーツと鍵盤の発光。小節線・拍の線・小節番号（MIDIの拍子記号から。なければ4/4）。音名（なし／ドレミ／CDE）。ノーツの色は手ごと（右＝緑、左＝青、初期値）かトラックごと。
- **鍵盤の範囲**：演奏パートに合わせる（初期値、最低でも白鍵10個）／全パート／25・37・49・61・76・88鍵。ノーツの所を2本指でピンチして増減、横に動かして移動（白鍵7〜52個）。PCはホイール、Shift＋ホイール。範囲の外にある自分のノーツは左右の端に印。
- **楽譜（簡易版）**：上に大譜表を出して横に流す。「演奏」のトラックを、右手はト音記号、左手はヘ音記号に。16分音符の格子にそろえ、音符の長さ（付点も）、和音、加線、調号（移調に合わせる）、臨時記号（小節内で記憶）、拍子。色：今鳴っている＝青、命中＝緑、ミス＝赤、練習していない手＝灰色。休符・連桁・タイ・3連符はなし。記号は Google Fonts の Noto Music。
- **MIDIの読み込み**：1つのトラックに複数のチャンネルが入っている曲（フォーマット0。市販のGS/XGの曲に多い）は、チャンネルごとに別のトラックに分けて表示する（名前は「トラック名 Ch番号 楽器名」）。以前は最初の音のチャンネルでトラック全体を決めていたため、ドラム（Ch10）から始まる曲が全部消音になり、何も出ず鳴らなかった（2026/10/24 に修正）。
- **トラック**：演奏／自動／消音、右手／左手／分割（設定した高さから上が右手。初期値C4）、トラックごとの音量。初期値は、いちばん高い音域のトラックが「演奏」、ドラム（Ch10）は消音、手はトラック名（right/左 など）→演奏トラックは分割→ほかは平均の高さ。
- **弾き方**：MIDIキーボード（Web MIDI、ペダルCC64にも対応）、画面の鍵盤（マルチタッチ、指をすべらせると切り替わる）、パソコンのキーボード（Z〜/ と Q〜] の2段、← → でオクターブ、スペースで再生／停止。物理キーの位置で判定）。
- **練習**：通常／待つ（弾くまで止まる。和音は「全部押すまで」か「どれか1音で」。判定線の0.08秒前より早い入力は数えない）。両手／右手／左手（弾かない手は自動で鳴る）。区間ループ（小節単位。ボタン2回か小節番号の入力）。テンポ25〜150%（5%刻み）。メトロノーム（小節の頭は高い音）。再生前の1小節カウント。移調（±12半音、曲を開くと0に戻る）。
- **運指**：「運指を書く」をオンにして、ノーツを押すたびに 1→5→なし。PCは数字キー。曲名と音の数をキーにして localStorage に保存。
- **採点**：ぴったり（±0.05秒）／早い／遅い／ミス／余計な音、コンボ。判定の文字を判定線の上に出す。曲を最後まで通すと結果画面（ランクS〜D、星、点数、内訳）。点数＝(ぴったり×100＋早い遅い×70)÷(判定数×100＋余計な音×50)。自己ベストを曲ごと・「通常/待つ」×「両手/右手/左手」ごとに保存（曲の頭から、ループなしのときだけ）。
- **音**：高音質（FluidR3_GM を gleitz.github.io/midi-js-soundfonts から楽器ごとに読み込み。MIDIのプログラムチェンジで楽器を決める。読み込むまでと失敗したときは内蔵の音）／ピアノ（内蔵）／シンプル。ドラムは簡単な合成音。MIDIファイルのペダル（CC64）で音を伸ばす（最大10秒、設定で切り替え）。
- **最近開いた曲**：設定のいちばん上。最大10曲、MIDIの中身ごと localStorage に保存。自己ベストも表示。
- **設定の保存**：表示・音・練習の設定は localStorage に保存。
- **アクセス数**：配布ページとソフトで GoatCounter（ドラム側と同じ pikadrum.goatcounter.com）を使う。配布ページの下に、/keys/ のページの数だけを表示（ドラム側のページの数は含まない）。保存したファイルを直接開いたときは数えない。
- **このソフトについて**：設定のいちばん下に、配布ページ・音色のクレジット・ドラム練習スコープへのリンク。

## 同期の実装（鍵盤側）
仕様は drum リポジトリの `同期の仕様.md`（v1）のとおり。鍵盤側は `app:"keys"`。
- 同じ端末は BroadcastChannel `pikadrum-sync`、別の端末は PeerJS 1.5.4（unpkg から読み込み、部屋番号4〜8桁、ID `pikadrum-sync-<部屋番号>`）。親か子かは自動で決まり、親が抜けたら引き継ぐ。親は中継する。両方につながっていれば、同じ端末側と別の端末側の間も中継する。
- 時計合わせは tping/tpong を8回、往復が最小の回のずれを使う。
- 送る type：hello / state / tick / song / ping / bye。`mid` で重複を捨てる。`metro` と `mm`（ドラム側だけの type）は無視する。
- `pos` は原曲テンポの秒。音の遅れ（ms）の設定あり（送るとき −、受け取るとき ＋ 遅れ×rate）。
- `state` は、再生・停止・シーク・テンポ・ループ・トラックの演奏/自動の変更のときに送る（変わったときにすぐ送る。定期的な見張りはしていない）。受け取って合わせた変化は送り返さない。
- `tick`：リーダーだけが1秒ごと。8ms以下は何もしない、250msまでは1回最大10msずつ半分戻す、それより大きければ鳴らし直す。ループ中はずれをループの長さで折り返して比べる。
- `loop`：`{a,b}`（小節、1から）を送受信。ループの頭に戻るときは各端末が自分で折り返し、`state` は送らない。
- `countFrom`：カウントがオンなら、再生を始めたときに `countFrom`（曲が鳴り始める位置）と、1小節前の `pos` を送る。受け取ったら、鍵盤側のカウントがオンのとき残りの拍を鳴らす。カウントがオフで再生を押したときは、約1.2秒後に始まるよう `pos` を前にずらして送る。
- `rate`：25〜150%（5%刻み）を選べる。ほかの値を受け取っても、そのまま合わせる。
- `plays`：「演奏」にしたトラックのチャンネル（1〜16）を送る（片手練習のときもチャンネル全体）。相手の `plays.channels` のチャンネルを自分の自動伴奏から消す（設定で切り替え）。
- `song`：MIDIを開いたとき（最近開いた曲から開いたときも）と、`hello` を受け取ったときに送る。`name` は拡張子なし。受け取ったら開き（設定で切り替え）、直後に最後に受け取った `state` を当て直す。受け取って開いた曲は送り返さない。
- 送らないもの：移調、運指、手の分け方、音色、採点。

### ドラム側と合わせて確認したこと
- 小節の数え方：どちらも曲の最初（ティック0）を1小節目、拍子記号がなければ4/4。弱起も特別扱いしないので同じ（2026/10/23、ドラム側の引き継ぎより）。
- ドラム側と鍵盤側を実際につないだテストは、まだしていない（ユーザーの意向で保留）。

### 仕様どおりになっていないところ
- 仕様3-3の2つ目（相手の `plays.drums` が true なら自分のドラムの音を消す）は入っていない。鍵盤側はドラムのトラックを初期値で消音にしている。
- 「待つ」モード中は、鍵盤側が止まっても `state` を送らず、`tick` も送りも使いもしない。そのため、待つモード中はドラム側とずれる（下の提案を参照）。
